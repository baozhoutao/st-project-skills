# traps — 验收判定陷阱清单(判 ❌/✅ 前的必经关卡)

> 用法:任何案例判 **❌ 不通过** 前,逐条过「假阴性」区,把已排除项写进
> results.json 的 `traps_checked`;判 **✅ 通过** 前自查「假阳性」区。
> 本文件是活文档:验收中新踩的坑要追加进来。

## 假阴性区 —— 别把这些判成产品缺陷

| # | 陷阱 | 排除动作 |
|---|---|---|
| N1 | 记录页头 5–15s 水合半加载窗口 | 等待并刷新后再断言;别在半加载态截图定罪 |
| N2 | 页头动作只渲染前 N 个,其余折进「更多操作」 | 判「按钮不存在」前必展开更多菜单 |
| N3 | 视口宽 <640 列表自动走卡片流 | Console 用桌面视口;布局变了不等于列表坏了 |
| N4 | lookup 多选回显慢且无 loading | 等回显完成再判空 |
| N5 | create-user 带改密标记 → 登录 200 但接口全 403 | 该账号先走 change-password 解除,再测 |
| N6 | 登录路由 404(如手机号登录) | 先查是否绕过了项目 package.json 标准启动脚本(环境变量丢失),不是产品缺陷 |
| N7 | 幽灵进程 / 端口漂移 / 共库污染 | `lsof` 按端口核 serving 进程唯一性、cwd 与库路径 |
| N8 | 陈旧基线(热重载日志会骗人) | 按端口重启取证;核实 serving commit 已含被验收改动 |
| N9 | sys_metadata 物化 view 陈旧 → 新列不显示 | 先排这个再定罪(DELETE 该行 + 重启) |
| N10 | Console 交互点不动 / 403 伪装成网络错误 | 换既有探针脚本的成熟选择器路径重试一次 |
| N11 | toast 瞬时,没抓到 ≠ 没弹 | waitFor 抓拍;没截到就复跑,不凭没截到判失败 |
| N12 | expand 无读权静默降级成裸 id | 这是权限配置问题的症状——按案例指定角色验,别当渲染缺陷报 |
| N13 | H5「无权 / 加载失败 / 真空」三态 | 「—」≠ 0 ≠ 403,先分清是哪一态再下结论 |
| N14 | 案例写的按钮/菜单名与 UI 不一致 | 先过 N2;仍不一致 → ⚠️ 记录「文件写X实际Y」交 PM,不脑补替换 |
| N15 | 权限异常可能是测试账号没配对,不是产品缺陷 | 判权限类 ❌ 前先核对该账号的岗位、权限配置是否合理(对照项目权限基线与案例指定角色);配置不对按环境问题修复重跑,配置合理仍异常才定罪 |

## 假阳性区 —— 别把这些判成通过

| # | 陷阱 | 自查动作 |
|---|---|---|
| P1 | admin 跑通 ≠ 目标角色通过 | 判定账号必须是案例指定角色;权限类案例加零授权对照 |
| P2 | toast 成功 ≠ 数据落库 | 关键写操作补第二观察点:列表/详情回读到新值才算 |
| P3 | 种子数据碰巧满足预期 | 没有 before 对照就证明不了因果;必须有前置状态截图/计数 |
| P4 | 「更新成功」与「部分字段未保存」并列的假告警 | 以字段最终值为准,别看提示语下结论 |
| P5 | 无报错 ≠ 成功 | 预期怎么写就怎么验,逐条对,不用「没报错」替代 |
| P6 | 截图与旁白脱节 | 每张截图落盘后必须 Read 回看,确认内容支撑 observed,回看结论写进 `shows` 图注;截图前复位取景 |

## 截图操作规范(证据合格线)

- 命名:`AC-XXX-<步骤号>-<观察物>.png`,每批次独立目录,禁覆盖已 commit 的证据。
- H5:390×1180,禁 fullPage;落盘走全局 playwright + channel chrome(Browser 面板存不了盘)。
- Console:桌面视口(≥1280 宽)。
- toast / 瞬时态:waitFor 抓拍。
- before/after 成对:写操作案例先抓前置状态(列表计数、记录不存在),后抓结果态。
