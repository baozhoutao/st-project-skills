# blueprint-template — 总体方案蓝图文档骨架

> 用法:SKILL.md 流程 ①~⑥ 按本骨架成稿,⑦ 按更新记录规则增量维护。示例均为通用
> 业务(库存/报销类),与任何具体项目无关;客户名、系统名、环境地址只出现在项目
> 自己的文档里,不回写本库。
>
> **两条体量原则:①「总览」一页读懂全项目——统计数字与正文逐节对得上,对不上 =
> 文档不合格;②逐条明细住在各章表格里,平台配置细节一律引用平台 skill 不展开。**

## 文档结构总览

| 章节 | 内容 | 谁引用它 |
|---|---|---|
| 文档信息 | 基准版本、输入清单、审定记录 | 判断这份蓝图可不可信 |
| §1 | 总览(关键数字一页) | 技术负责人 30 分钟审定的入口 |
| §2 | steedos 能力映射清单 + 汇总统计 | 平台升级评估 / 复盘校准 / 下一单报价 |
| §3 | 对象模型总图 | dev-design 判「跨模块/改已有」 |
| §4 | 集成接口台账(全文见 integration-ledger) | 联调排期与责任追踪 |
| §5 | 模块依赖与建议开发顺序 | pm-dispatch 依赖分组 |
| §6 | 与报价工作项清单对账结果 | PM 判变更信号 |
| §7 | 待验证项关闭记录 | 核对 pre-intake 粗判是否清零 |
| 更新记录 | 版本 × 修正号/CR 号 | 核对蓝图与基准同步 |

## 送审前自检清单(逐条过)

- [ ] 文档信息区写明「基于 SRS V<x> + 修正 1..N」,与 req-baseline 台账对得上;
- [ ] §1 关键数字与 §2~§7 逐节对得上(对象数、用量、接口数、差异数、待验证数);
- [ ] §2 每条映射有 SRS 出处与判定依据,通篇搜不到「应该可以」;
- [ ] §2 汇总统计表齐全,不涉及的类别填 0 不删行;定制点计数单列;
- [ ] §2 通篇无平台配置细节(判据:出现具体配置项/参数写法 = 超纲,改为引用平台 skill);
- [ ] §3 共享对象逐个标出被哪些模块读写;
- [ ] §4 有个数统计行;零集成时明写「零外部集成」,无空白页;
- [ ] §5 每条依赖带理由;有环的如实标出;
- [ ] §6 差异清单每条有报送记录;无报价清单时明写并已报 PM;
- [ ] §7 pre-intake 待验证项全部关闭或带期限;
- [ ] 更新记录首行为 V1.0 审定;后续版本逐行对应修正号/CR 号。
