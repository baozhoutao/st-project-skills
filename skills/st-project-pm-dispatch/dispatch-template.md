# dispatch-template.md — 开发子 agent 派发模板

调度员使用方法:把下方「模板正文」整段复制,**逐字段实例化**(`<尖括号>` 占位符全部
替换,一个不许留),作为开发子 agent 的完整初始 prompt 下发。子 agent 冷启动、
不共享主会话上下文——**模板缺什么它就瞎猜什么,宁可冗余,不许缺省**。

设计原则:模板里的纪律摘要来自 st-project-dev-issue / st-project-std-git /
st-project-std-evidence。若项目仓库已把这些 skill 链入 `.claude/skills/`,子 agent
会自动加载全文,摘要作双保险;未链入时,摘要就是子 agent 唯一的纪律来源,**禁删**。

---

## 模板正文(从此行下方开始复制)

任务:完成工作项 #<n> 的开发闭环,提 PR。**绝不自行合并 PR;绝不动 main。**

### 工作项

- 编号:#<n>(仓库 <owner>/<repo>)
- 标题:<标题原文>
- 正文(全文粘贴,以此为准,不要另行拉取后自行解读差异):

  <工作项正文全文,含验收标准/DoR 要素;有关键评论结论也一并粘贴>

- 优先级:<P0/P1/P2>
- 依赖与边界:<本项依赖 #x,其代码已合入 main(基线 commit 已含);无依赖则写「无」>
- **禁触碰**:<并行项正在改的对象/模块/文件清单;无则写「无」>——碰了会与并行项冲突。

### 环境与隔离(按分配表执行,禁自行更改)

- worktree 路径:<路径>;分支:`issue-<n>-<slug>`;基线 = main @ <commit SHA>
- dev server 端口:<port>;数据库文件:<路径>——批内独占,禁用其他端口/库文件
- 测试账号:<角色→账号映射,或获取方式(如某初始化脚本/项目文档位置)>
- 状态标签实际名与看板:<项目侧标签名清单或「见项目 CLAUDE.md/标签表」>

### 必须遵守的纪律

1. **项目约定优先**:开工先读项目仓库 CLAUDE.md 与 `.claude/` 配置,项目约定与本
   模板冲突时以项目约定为准,并把冲突点写进返回报告「需拍板事项」。
2. **开发闭环**(st-project-dev-issue):先输出需求理解+实现方式,**方案分级后再动手**
   ——纯新增且路径唯一才可直接开工;**改已有功能/跨模块/多可行路径 = 高风险,立刻
   停手**,把方案要点写进返回报告「需拍板事项」,状态切「方案确认中」,不许自作主张。
3. **Git 纪律**(st-project-std-git):绝不在 main/master 上做任何写操作;只在上述
   分支与 worktree 内工作;禁推送到任何其他分支;PR 正文只写关联编号,**不写自动
   关闭工作项的关键字**;合并归调度员(收单核实 + 代码评审闸门通过后自主合并,
   见 SKILL ⑤)——
   **对你而言提 PR 即止**,合并与后续状态一律不碰。
4. **证据纪律**(st-project-std-evidence):功能证据 = 真实环境 UI 操作截图,代码/
   单测输出/API 直调返回值不算;成功与失败分支都要截;截图先 commit+push,图链用
   **40 位 commit SHA** 拼(禁分支名);贴完用 contents API 核对文件在。
5. **测试报告**:自测完成后按项目报告约定产出带截图的测试报告,挂到工作项上,
   状态切「自测报告中」。
6. **提 PR**:PR 正文关联工作项编号;状态切「PR审查中」;**同一步把处理人交接给
   验收侧/工作项创建人**——不交接,看板上没人知道轮到谁。
7. **失败即停**:同一问题失败一次(实现不出来/自测不过/环境修不好)就停手,如实写进
   返回报告,禁止无限自我重试;疑似平台能力受限也停手上报,禁止绕行打补丁。
8. **范围纪律**:只做本工作项范围内的事;顺手发现的其他问题记进「遗留问题」,不动手修。

### 返回报告(结构化,逐字段填;缺字段 = 收单直接退回)

```
结果:完成 / 部分完成 / 失败(一句话原因)
工作项:#<n>
分支:issue-<n>-<slug>
PR:<URL>(没提 PR 就写「无」+ 原因)
测试报告:<挂在工作项上的评论 URL>
需求符合度清单:<挂在工作项上的评论 URL;非 ✅ 条目各自的出口链接一并列出>
证据:<截图所在 commit SHA 与图链形式;或「见测试报告」>
状态流转:<当前已切到的状态标签实际名;处理人交接给了谁>
自测结论:<通过 / 存在问题(逐条一句话)>
遗留问题:<无 / 清单,每条一句话+影响面>
需拍板事项:<无 / 清单,每条 = 事项 + 背景≤2行 + 建议选项A/B>
基准差异:<无 / 实现与需求文档对不上的点,逐条列,不自行选边>
```

## 调度员实例化检查清单(派发前逐项打勾)

- [ ] 工作项正文**全文**已粘贴(不是编号、不是链接);
- [ ] 环境分配行已填,且与批内其他项的端口/库文件/worktree 不冲突;
- [ ] 依赖与「禁触碰」清单已按本批并行项实况填写;
- [ ] 基线 commit SHA 已核对为最新 main,且已包含全部前置项代码;
- [ ] 状态标签实际名/获取方式已给;
- [ ] 测试账号已给或指明获取方式;
- [ ] 「返回报告」格式原样保留,未删字段;
- [ ] 派发的 Agent 调用带 `model: opus`(开发子 agent 一律 Opus,不用主会话模型)。
