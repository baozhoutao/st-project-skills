# templates — 细化三模板

> 用法:流程 ④ 疑点收敛用模板一;⑥ 自证就绪用模板二;⑦ 打回用模板三。
> 评论发布方式按项目仓库的工具链执行(如 GitHub issue 评论),本 skill 不约定具体命令;
> 仓库、标签等项目上下文一律从项目配置 / git remote 读取,不写死在模板里。
> 示例均为通用业务示例(报销类),与任何具体项目无关。

## 模板一:AI 理解与疑点(选择题)

```markdown
## AI 理解与疑点(供拍板)

**我的理解**:<2~3 句复述这条需求的业务目标与主流程,纯业务语言>

**假设**(未经确认;细化将按此进行,不对请指出):
1. <假设一,写成可证伪的陈述句>
2. <假设二>

**需拍板**(每题从选项中选一个,或直接给出选项外的答案):

**Q1 <一句话问题>**
- A. <选项 A> → 连带影响:<选 A 则……>
- B. <选项 B> → 连带影响:<选 B 则……>
- 建议:<A/B>。理由:<一句话;优先引用基准锚点,如「与 SRS §3.2 的〈…〉一致」;
  其次才是「改动面最小」这类工程理由>
```

示例(通用业务):

> **Q1 报销单金额超 5 万时,是拦截提交还是转高层审批?**
> - A. 拦截提交,提示「超出单笔上限」 → 连带影响:输入时即时校验,审批流不变
> - B. 允许提交,状态置「待总监审批」 → 连带影响:审批流加一级,总监需收到通知
> - 建议:B。理由:基准 §4.1 写明「大额报销由总监加签」,选 A 与基准冲突。

硬规则:

- 每题选项**互斥且尽量穷尽**:明知还有 C 就写出 C,不许用两个选项框住 PM;
- 每题必须带建议与理由;理由引用基准优先于工程偏好;
- **禁止开放式问题**(「这里想怎么做?」)——写不出选项,说明 AI 还没做完功课
  (读基准 / 读现状),回去做完再来;
- 一个工作项的疑点**攒成一条评论一次提交**;拍板后答案回填描述正文(硬)。

## 模板二:测试计划草稿(就绪证明)

> 用途只有一个:证明「仅凭工作项描述就能写出测试计划」。写作时**只看工作项描述**——
> 不翻基准、不翻代码、不翻对话记录;要翻别的材料才写得出来 = 描述不自包含 = 缺口。
> 它不是正式验收用例(那是 st-project-pm-case 的活),不回填、不维护、不进代码仓库。

```markdown
## 就绪证明:测试计划草稿(仅凭本工作项描述写出)

| # | 测试点 | 操作 | 预期(在哪里看:看到什么) | 依据(描述哪一段) |
|---|---|---|---|---|
| 1 | 主流程-导出成功 | 财务角色筛选后点【导出】 | 下载 xlsx,行数 = 列表条数 | §输出/反馈 |
| 2 | 校验-金额为 0 | 金额填 0 保存 | 拦截,提示「金额必须大于 0」 | §校验规则第 1 条 |
| 3 | 校验-金额正常 | 金额填 100 保存 | 保存成功,列表出现该单 | §校验规则第 1 条 |
| 4 | 权限-无权角色 | 无导出权限角色打开列表 | 看不到【导出】按钮 | §验收标准第 2 条 |

**覆盖自查**:主流程 n 条;校验规则 n 条 × 正反;权限正反 n;联动 n(描述写明无联动则注明)
**写不出的点(= 描述缺口,非空即打回)**:无 / 逐条列出缺口在描述的哪一处
```

硬规则:

- 「依据」列必须指向描述的具体小节/条目;指不到 = 该行是假设,挪进「写不出的点」,
  不许伪装成有依据;
- 覆盖自查与描述对不齐(如描述有 3 条校验规则、草稿只覆盖 1 条)= 草稿不完整,
  不构成就绪证据;
- 草稿以评论挂工作项,不进描述正文、不进代码仓库。

## 模板三:打回意见(缺什么 / 补什么 / 补到什么程度算好)

```markdown
## 未过就绪判定,保持「待细化」

**已合格**:要素 1 / 2 / 3 / 6 齐全,无需重写。

**缺口 1(七要素-4 校验规则)**
- 缺什么:「金额校验」只写了要校验,没写不通过时系统怎么反应
- 补什么:金额不合规(为 0、为负、超上限)各自是拦截还是放行?提示文案是什么?
  (建议参照:基准 §4.1 大额加签条款)
- 补到什么程度算好:能照着写出一条反例测试——「输入 X → 在哪里看到什么提示」;
  例:「金额填 0 → 保存被拦截,表单提示『金额必须大于 0』」

**缺口 2(七要素-7 验收标准)**
- 缺什么:……
- 补什么:……
- 补到什么程度算好:……

补齐后我重新核对判定。
```

硬规则:

- 每个缺口三段齐:**缺什么**(指到七要素第几项)/ **补什么**(具体问题,能做成选择题
  就做成选择题)/ **补到什么程度算好**(给一句合格样例);
- 打回必须可执行:PM 读完 30 秒内知道要补哪几句话;「描述不够详细,请补充」这类打回
  是本模板最严重的违规;
- 开头必须先说「已合格」的部分——打回是补缺口,不是全盘否定,防止 PM 全文重来。
