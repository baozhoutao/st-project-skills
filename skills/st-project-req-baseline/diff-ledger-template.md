# 差异登记台账模板

> 配套 [st-project-req-baseline](SKILL.md) 第三节使用。台账文件的存放位置按项目仓库
> 约定(建议与 SRS 工作版同目录);一个项目一份台账,`DIFF` 编号与「修正」编号
> 都是全项目顺号。

## 使用规则(先读)

1. **只增不改**:差异编号 `DIFF-NNN` 和修正编号「修正 N」写错了、被推翻了,都是
   出新条目引用旧条目,不回改历史正文;
2. 登记时只填「登记区」;拍板后补「拍板区」,并在「修正记录」章节同步落一条修正;
3. AI 只做登记、上报、按拍板结论落地;拍板区的「结论」只能填人拍板的原话/纪要,
   不能填 AI 的倾向;
4. 台账总表是索引,随条目状态更新;条目正文是真值,两处不一致以条目为准。

## 台账总表(放文件开头,一行一条)

| 编号 | 一句话现象 | 登记日期 | 状态 | 修正号 |
|---|---|---|---|---|
| DIFF-001 | (示例)X 功能实际行为与 SRS §N 描述相反 | YYYY-MM-DD | 已拍板 | 修正 1 |
| DIFF-002 | (示例)SRS §A 与 §B 对同一口径说法矛盾 | YYYY-MM-DD | 待拍板 | — |

状态流转:`待拍板` → `已拍板` → `已落地`(修正涉及的 SRS 更新与代码工作项全部完成);
另有 `已合并`(与其他条目重复,注明并入哪条,不删行)。

## 差异条目模板(逐条复制)

```markdown
### DIFF-NNN:<一句话概括>

#### 登记区(登记时填)

- 登记人/日期/发现途径:(谁、何时、在哪个环节撞见——开发自测 / 验收走查 /
  细化核对 / 试运行 / 客户反馈)
- 现象:在哪里看到什么(可复现的描述;有截图/记录的挂链接)
- 两边说法(逐方引用原文,带出处锚点):
  - SRS/文档侧:§章节号 + 原文摘引
  - 代码/实现侧:实际行为描述(+ 关键入口/位置)
  - 其他说法(工作项描述、会议纪要等,有才列):出处 + 摘引
- 影响面:涉及哪些功能/端/角色;是否疑似涉客户口径(疑似 → 明写「疑似涉客户
  口径,请 PM 考虑是否升级客户确认」)
- 紧急度:是否阻塞在途开发(阻塞 → 即时上报,不等攒批)
- AI 倾向(仅参考,不构成默认;无倾向写「无」):倾向哪边 + 理由;疑似笔误的
  标注「疑似笔误,建议快裁」

#### 拍板区(拍板后填)

- 拍板人/日期:
- 结论:以哪边为准 / 第三种口径(记原话或纪要摘引)
- 修正号:修正 N
- 波及动作:改 SRS 工作版(§章节)/ 改代码(列工作项编号)/ 两者都改
```

## 修正记录(台账文件内独立章节,顺号追加)

```markdown
### 修正 N(YYYY-MM-DD,拍板人:XXX)

- 对应差异:DIFF-NNN
- 结论:…(正式记录,与条目拍板区一致)
- SRS 落地:工作版 V x.y 已按本修正更新 §章节(签字版不动);
  暂未落 SRS 的写明原因与责任人
- 代码落地:对应工作项编号 / 无需改代码
```

- 修正被推翻时:新修正正文写明「推翻修正 N,改为…」;可在旧修正末尾**追加**一行
  指针「→ 已被修正 M 推翻」,但不得改动旧修正的结论正文;
- 读当前有效基准的方法:签字版 + 按号通读修正记录,后号覆盖前号。
